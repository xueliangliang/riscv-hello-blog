## 二十多年前，我觉得操作系统课像文科

二十多年前上[操作系统（Operating System，OS）](/terms/#os)课时，对当时的我来说，这门课有点像文科：要记各种设计原则、术语和机制，考试时也能把它们复述出来；可一问“这些东西在程序运行时到底怎样发生”，脑子里就容易变成一团雾。

这不是说理论不重要，也不是要评价当年的老师。问题在于我一直缺少真正动手的机会。进程、调度、文件系统、中断、虚拟内存……名字都见过，原则也背过，却很难把它们和一段正在执行的代码、一串寄存器变化、磁盘上的实际字节联系起来。

后来一直想补上这段实践，但总有别的事情排在前面。现在正好借这个机会，从一条指令开始，把整个过程重新捋一遍。

## 这次不从原则背起，从能观察的现象开始

我想沿着一条连续的路径做下去：

1. 从源码和交叉编译开始，生成[可执行与可链接格式（Executable and Linkable Format，ELF）](/terms/#elf)文件；
2. 找到入口并写启动汇编，设置 C 运行环境；
3. 通过[通用异步收发器（Universal Asynchronous Receiver-Transmitter，UART）](/terms/#uart)得到第一行串口输出；
4. 让 bootloader 从块设备读镜像，再逐步增加特权级、syscall、调度和 shell；
5. 加入文件系统和持久化，再让系统自己编译、加载和动态调用程序；
6. 最后把已经在模拟器里逐层验证的系统移到真实开发板。

每一步都尽量能回答四个问题：

1. 现在要解决的具体问题是什么？
2. 改动了哪些代码、寄存器或磁盘字节？
3. 我预计运行时会看到什么？
4. 实际测试结果是否和预测一致；哪些边界仍未覆盖？

这条路线不是“从零造出一个可替代 Linux 的 OS”。它是一套小而可复现的教学实验：从 [QEMU（Quick Emulator，快速仿真器）](/terms/#qemu) 中的一行串口输出，逐步走向内核服务、持久化和真机验收。哪些能力尚未实现，也会明确写出来。

## 人工智能（Artificial Intelligence，AI）辅助的费曼学习法

我把这个过程称作 [AI 辅助的费曼式学习](/terms/#ai)。AI 可以帮我拆解问题、解释陌生机制、提出实现草案、一起读错误信息；但它给出的答案不是验收结果，更不能替我理解系统。

实际循环应该是：

```text
选一个小问题
  → 让 agent 协助解释或实现
  → 我检查设计和 diff，先预测结果
  → 自己构建、运行、测试，必要时用 [GNU 调试器（GNU Debugger，GDB）](/terms/#gdb)或独立脚本核对
  → 用自己的话讲明白，并记录没验证到的部分
```

如果我不能解释启动时[栈指针（stack pointer，`sp`）](/terms/#sp)为什么必须先设置，或者 bootloader 读的[逻辑块寻址（Logical Block Addressing，LBA）](/terms/#lba)怎样对应到[随机存取存储器（Random-Access Memory，RAM）](/terms/#ram)地址，那就还没有真正学会。测试通过也只说明测试覆盖的那条路径通过了，不自动证明整个机制没有缺陷。

因此文章不会以聊天记录为主线，也不会把“agent 说完成了”当结论。真正值得记录的是：曾经哪里理解错了、如何定位、代码和实验给了什么证据，以及最后仍有哪些限制。

## 为什么选 RISC-V 和 QEMU

> 本节于 2026-11-06 补充。下面把能查到来源的事实，与我对未来应用的判断分开；产品与平台资料不等于本系列已经做过相应硬件测试。

并不是其他架构不能学操作系统，而是 RISC-V 给了我一条比较连贯的路径：公开的架构规范、能读懂的教学内核、方便重复实验的模拟器，以及可以继续研究的开源处理器实现。我希望先把这条路径走通，而不是一开始就被某块板子的启动细节卡住。

### 有 xv6 作为可对照的教学系统

一个重要原因是 [xv6](https://pdos.csail.mit.edu/6.828/2026/xv6.html)。它是受 Unix V6 启发的类 Unix 教学操作系统，已有 RISC-V 版本、公开源码和配套教材。[MIT 的操作系统课程](https://pdos.csail.mit.edu/6.828/2026/overview.html)用它讲进程、系统调用、中断、页表、并发和文件系统：它保留了值得研究的真实机制，又比 Linux 这样的生产内核小得多。

这对重新学习很重要。读到“系统调用”时，可以继续看用户代码怎样进入内核；读到“进程切换”时，可以追踪保存了哪些寄存器、下一段代码从哪里恢复。不必只停在概念解释，也不必立刻面对生产内核的全部复杂度。

本系列不是 xv6 的移植版，也不是照搬 MIT 的实验题，而是按自己的路线逐步搭起一个教学系统。xv6 是对照和延伸阅读：当我们的取舍更简化时，要说清为什么简化，不能因为用了相同的指令集，就默认已经具备 xv6 的页表、进程隔离或接口。

### 开放的是指令集，具体处理器是否开源要看实现

“RISC-V 是完全开放的 CPU 设计”这句话需要拆开。严格地说，RISC-V 首先是一套开放标准的[指令集架构（Instruction Set Architecture，ISA）](/terms/#isa)，规定软件能看到的指令、寄存器和行为约定；它不是某一颗[中央处理器（Central Processing Unit，CPU）](/terms/#cpu)的完整电路图。

[RISC-V International 的官方说明](https://riscv.org/about/)明确区分了标准与实现：采用开放的 RISC-V ISA 不需要支付该 ISA 的架构授权费，但实现可以是开源的，也可以是商业闭源的。流水线怎样设计、缓存怎样组织、具体电路是否公开，都不是“RISC-V”这个名字自动保证的；采购商用处理器核、设计工具、制造芯片也不会因此免费。

它吸引我的地方，是能把“读规范”继续接到“读实现”。例如 [lowRISC 的 Ibex](https://github.com/lowRISC/ibex)就是用 SystemVerilog 编写、主要按 Apache 2.0 许可证发布的开源 RISC-V 处理器核。学习者不仅可以观察软件如何使用指令，也有机会继续研究硬件如何实现指令。

所以，更准确的理由是：**RISC-V 的开放标准，让从公开规范走向开源实现成为现实选择，而不是保证每颗 RISC-V 芯片从电路到工艺都完全公开。** 对我来说，这保留了以后继续向硬件学习的入口；不代表本系列已经实现或验证了一个处理器核。

### QEMU 先帮我把实验变量控制住

选择 RISC-V，并不意味着第一天就要买板子。前期使用 QEMU `virt`，可以先固定一组虚拟设备和启动条件，反复观察串口、中断、块设备和内存状态。[QEMU 的 GDB 调试接口](https://www.qemu.org/docs/master/system/gdb.html)允许暂停、继续执行、检查寄存器和内存、设置断点，适合把“我预计会发生什么”逐步和实际执行对上。

这里固定的是代码版本、工具版本、启动参数和设备模型，不是保证每次并发执行的时序都一样。课程代码仓库再用标签固定每一课的状态，避免文章依赖不断变化的 `main`。

边界同样重要：[QEMU 官方文档](https://www.qemu.org/docs/master/system/riscv/virt.html)明确说，`virt` 是通用虚拟平台，不对应某块真实硬件。它提供的设备地址不是所有 RISC-V 板卡的统一地址。模拟器里运行成功，也不等于已经验证真机的启动链、时钟、中断接线、存储持久性或实际性能。等路线走到开发板时，这些条件都要重新核对，并实测每一层。

### 未来会用在哪里：先看落地，再谈判断

我不想靠“几年后替代谁”来证明这个选择。更值得看的，是它现在进入了哪些系统，以及继续扩展还缺什么。

- **嵌入式与物联网：已经是现实入口。** [乐鑫 ESP32-C6 的官方产品资料](https://www.espressif.com/en/products/socs/esp32-c6)列出了 RISC-V 处理器和无线连接能力。这不是只能运行在模拟器里的课堂架构。我的判断是，需要定制控制逻辑、固件和设备接口的系统，会继续是很实际的应用方向；但低功耗或低成本的优势仍取决于具体芯片实现，不能只看指令集名字。
- **专用计算与 AI 加速器：可以与计算单元协作，而不必替代整台电脑的处理器。** [Tenstorrent 的官方架构资料](https://docs.tenstorrent.com/tt-vscode-toolkit/riscv-guide/)说明，Tensix 单元里的 RISC-V 处理器分别参与数据搬运和计算管线，并与专门的矩阵、向量单元协作。这说明 RISC-V 可以成为更大计算系统的一部分；不能据此把“用了 RISC-V”直接换算成某种 AI 算力或性能优势。
- **汽车与工业控制：有推进信号，仍要跨过工程门槛。** Quintauris 于 [2026 年 11 月 3 日发布 EM-Altair 嵌入式平台](https://www.quintauris.com/em-altair-risc-v-platform-launch)，强调为汽车、工业和物联网建立更一致的执行环境。我把它看作生态在补平台兼容性的一块拼图，而不是所有相关芯片已经量产上车的证明。真正进入产品，还要看实时性、安全要求、工具和长期维护。
- **更复杂的通用系统：有标准化路线，不等于胜负已定。** RISC-V International 在 [2024 年 10 月宣布批准 RVA23 Profile](https://riscv.org/blog/risc-v-announces-ratification-of-the-rva23-profile-standard/)，通过约定必选与可选的架构特性，给操作系统和软件发行版更明确的目标配置。这不意味着所有 RISC-V 芯片天然兼容，或不同平台的外设、启动方式和性能相同。我的判断是，桌面和服务器上的竞争，还要同时解决处理器性能、内存与设备系统、驱动、应用生态和长期支持，不能只靠免 ISA 架构授权费得出结论。

因此，我选择它，不是要押注某个架构必然取代 x86 或 Arm，而是想用一个可以读、可以跑、也能继续向硬件追问的起点，把操作系统真正学一遍。将来换架构时，启动、异常与中断、并发和文件系统的知识仍有用；具体的寄存器、调用约定、内存行为和设备驱动，则必须重新核对。

## 目前走到哪里

序篇之后，前三课已经发布：

- 第 01 课：搭建可复现环境，进入第一条指令；
- 第 02 课：设置启动环境、进入 C `main` 并输出 UART；
- 第 03 课：从 virtio 磁盘加载 kernel 和 shell payload。

从[机器模式（Machine mode，M-mode）](/terms/#m-mode)到[用户模式（User mode，U-mode）](/terms/#u-mode)、调度、文件系统、编译器和真机移植仍在路线图上，不会因为标题出现在总览里就算已经完成。

可以从[系列总览](/series/)查看每一篇的状态；每篇技术课都会给出对应代码标签、复现命令和实测验收。希望多年以后再回头看时，我不只记得操作系统有哪些原则，也能沿着代码和运行结果，把它们从头讲清楚。
